# 任务匹配与生产选择

按对象、场景、问题、目标、漏斗阶段、证据、素材和平台选择结构，再选开场。不要先套模板再寻找主题。

## 开场选择

1. 优先读取 `shared/opening-hooks.jsonl`（20类口播开场公式）；旧 `shared/hooks.jsonl` 的12类通用钩子保留为兼容基础，不作为唯一候选池。
2. 从不同心理机制中选3–6个候选，不用同一逻辑换同义词凑数。
3. 按受众相关性、具体程度、承诺可兑现性、证据可得性、平台适配、拍摄可行性筛选。
4. 最终开场必须明确“关用户什么事”，并在正文前段兑现承诺。
5. 钩子是创作方法，不是已验证的流量规律；所有新增公式的效果状态默认 unknown。

## 用户价值

按 `shared/audience-value-translation.md` 将功能/术语翻译为用户场景、问题、影响、解决机制、可见结果、证据和适用边界。每条视频只保留一个核心问题。

## 正文与证据

- 依据内容类型从 `shared/formulas.jsonl` 选择正文结构。
- 案例、数据、客户原话、演示和效果必须有来源；假设场景需显式标注。
- 开场承诺、标题/封面表达、正文内容和结尾行动必须一致。
- 具体时长和信息节奏按口播速度、复杂度和画面决定，不套固定秒数/字数阈值。

## Calling 与评论引子

按 `shared/cta-comment-seeds.jsonl` 选择一个主要行动；评论问题应能帮助理解真实需求或产生下一条内容，不以利益交换、胁迫或虚假承诺换互动。

## 证据分层

官方规则/平台公开说明、项目资料、真实账号数据、创作假设分别记录。算法权重、流量阈值和推荐机制无官方证据时标 UNKNOWN 或 INFERRED，不作为硬性规则。

## 去 AI 味与真人表达（v1.4.1）

1. 初稿完成后、交付前，必须按需读取 shared/human-voice.md、shared/human-voice-patterns.jsonl 与 shared/creator-voice-profile.md。
2. 先冻结事实、数字、主体、限定、作者判断和承诺；再做朗读测试与“盖住原稿重新说”测试。
3. 语言模式命中只是提醒，不得按关键词自动删改；技术术语、真实对比、必要限定和作者稳定口吻可以保留。
4. 禁止注入假第一人称、客户案例、无源数字、表演式坦诚、强行口语词和固定三点结构。
5. 同批稿件横向检查开场、结构、过渡、节奏和Calling是否同质；没有历史稿件时不声称完成跨期比较。
6. “去 AI 味”指减少模板化和不自然表达，不是AI检测规避，也不承诺任何AI检测分数。

## 225条标题公式的上游边界

sources/title-formula-to-hook-mapping.md 与原始文件是标题策略素材库。流程必须是：标题策略 → 提取人群/场景/问题/收益/信息差 → 选择口播心理机制 → 写成自然口语 → 校验画面与正文兑现。不得将225条标题句式直接当作225条口播钩子。
