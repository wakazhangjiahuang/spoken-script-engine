# AI视频口播表达合同｜Expression Contract 2.0（V4.1）

## 写稿前表达契约
每条脚本先记录：受众真实语言、当前认知、希望改变、核心矛盾、选定营销入口、点击理由、承诺与正文兑现、证据计划、下一层价值和禁止主张。它是内部决策字段，不是给用户看的冗长分析。

## 完整表达链
封面主标题 → 封面副标题 → 0–3秒开场 → 3–8秒承接 → 正文首段 → 证据/过程 → 核心结论 → Calling → 评论钩子。

| 节点 | 职责 | 必须做到 | 失败信号 |
|---|---|---|---|
| 主标题 | 识别主题与价值 | 让共同任务受众认领内容；陈述/结果/方法/故事/问句均可 | 作者自述、只堆工具、只有情绪 |
| 副标题 | 补足理解缺口 | 新增场景、方法、范围、证据、情绪或观看回报 | 重复主标题、第二主题、无法兑现的悬念 |
| 0–3秒 | 停留理由 | 身份/问题/现场/结果的自然口语 | 复读封面、自我介绍、泛泛开场 |
| 3–8秒 | 继续观看理由 | 新信息、证据预告或故事方向 | 复读开场、空壳悬念、把Calling放在前8秒 |
| 正文 | 兑现 | 欲望/疑虑/推进/证据或方法/结论与边界 | 工具菜单、抽象价值、没有信息增量 |
| Calling | 单一主要行动 | 说明为什么做、需要什么、下一步是什么 | 评论+私信+关注多重索取，或空泛关注 |
| 评论 | 低门槛表达 | 与Calling同一目的，具体易答 | 机械复制Calling、索取隐私 |

## 跨字段语义测试
- 主标题→副标题：主题/利益与新增信息互补。
- 副标题→开场：同一用户利益或认知冲突，不机械复述。
- 开场→承接：第二句新增信息或证据方向。
- 承接→正文：正文开始兑现预告。
- 正文→Calling：本篇先给足答案，再自然连接下一层需求。
- Calling→评论：同一行动目的，但评论问题更具体、更容易回答。

## 候选竞争
新选题默认比较至少三个机制不同的入口：受众现实利益、未被意识到的机会、能力/工作流变化等。每个候选写明用户收益、点击理由、可兑现承诺、证据计划和风险。三个都不成立则退回研究。锁定标题不得改写，只可比较未锁定的辅助表达。

## 真人表达与AI味审查
检查抽象化、套路化、广告腔、机械节奏、作者中心、虚假口语化、人设不一致。词语清单只用于提醒，不作为无条件禁词表。每句检查“谁在说、对谁说、什么场景、是否自然说出口”。至少一名非作者真人朗读；未做标NOT_RUN。

## 负向模式
- “剪辑师天塌了”：岗位替代暗示超过当前证据。
- “问问AI开发老司机”：嘉宾身份占据表达位置，没有用户观看回报。
- “AI剪辑密码/成片如牛来”：语义不清，用户无法预测得到什么。
- “老奶奶都会/零门槛”：没有非专业用户独立操作证据。
- “喝杯咖啡的时间”：未包含配置、素材准备、渲染、返工和验收的时间承诺。
- “评论区calling”：把内部字段名读给观众。
- “裂变”但只有多平台分发：传播主张与证据不匹配。
- 仅凭原片声称“分析互动数据”：缺少后台数据来源。

## A01案例使用边界
A01是用户校准的结构参考，不是已验证爆款或通用模板。学习其受众锁定、旧认知挑战、信息缺口、按营销目标筛选片段、AI与人工分工、正文兑现后升维到内容资产库的逻辑；不复制原词、句式或七步流程。
