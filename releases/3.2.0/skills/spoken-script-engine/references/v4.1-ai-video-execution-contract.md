# AI-video V4.1 public execution summary

This file is a redacted public summary of the private V4.1 standard. It intentionally excludes the original Word guide, raw A01 case text, original workbook, customer data and private source materials.

## Business route
AI-video tasks are routed by four independent dimensions: business line (A editing / B script-to-video / C authorized digital presenter), production mode (04 recording / 05 H3 / combined), commercial product (service / tool-template-Skill / training / enterprise workflow), and platform (Douyin / WeChat Channels / Xiaohongshu). These dimensions must not be conflated.

## Demand-first topic design
Select one primary demand layer: current pain, latent opportunity, or leverage value. Identify one shared user task, a concrete audience, the user's own language, a specific viewing payoff, evidence and the commercial next step. Do not treat an AI feature as a user need.

## Expression chain
Cover main title → cover subtitle → 0–3 second opening → 3–8 second bridge → body → evidence → conclusion → one primary CTA → comment prompt. Each field must advance the same promise; the body must pay off the opening and cover.

## Decision gateway
Use deterministic rules for IDs, schemas, locked fields, evidence references and hard gates. Use fast screening for full-batch triage, deep review for counterarguments and semantic payoff, and an independent critic/human for external challenge. Record actual reviewer identity and independence level. Do not claim separate-model validation when the same model performed all roles.

## Evidence boundaries
Distinguish fact, inference and unknown. Efficiency and cost claims require full-process measurement; batch output counts only after acceptance; revenue claims require project and payment evidence; AI interaction analysis requires exported platform data or an authorized interface. Multi-platform distribution alone is not viral/referral growth.

## Release control
Use the eight-dimension V4.1 AI-video rubric (weights: 15/15/15/20/10/10/10/5) with 0–5 anchors. 70–74 requires revision, 75–84 is a candidate, 85–100 is a strong candidate. Hard-gate failure blocks regardless of score. Each Script_ID is reviewed separately; batch averages never release weak rows. Human voice, blind-user and real publishing tests are separate statuses.
