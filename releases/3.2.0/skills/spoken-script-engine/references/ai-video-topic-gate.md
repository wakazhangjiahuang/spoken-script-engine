# AI视频选题确认门禁｜Topic Gate 1.2（V4.1）

## 目的
先证明内容值得目标用户看，再生产脚本。主题词、AI功能或创作者自己的工作进展不自动构成用户需求。

## 每条候选的最小决策契约
`topic_id`、行业/业务线、平台、受众、发展阶段、购买角色、当前资源、当前情境、共同任务、用户问题、需求信号、用户语言、“关我什么事”、观看回报、核心矛盾、内容机制、AI改变环节（如适用）、证据计划、商业产品、漏斗阶段、平台理由、行动理由、同批差异、风险与验证状态。

## 三层需求
现实需求 / 潜在需求 / 杠杆价值。每条选一个主要切入层，不强制一条内容讲完三层。

## 候选角度竞争
默认比较至少三个真正不同的营销入口，区分受众利益、点击理由、承诺、证据、风险；不能用换词充数。选中一个主入口，其他作为被否决候选保存，写清否决理由。若没有可证明的候选，退回研究或淘汰。

## 反方检查
1. 不认识创作者或工具，用户仍有理由点开吗？
2. 这是不是作者想讲的功能，而非用户正在完成的任务？
3. 用户看完能复述什么新信息/判断/行动？
4. 正文能兑现封面与开场吗？
5. 强主张有原始证据吗？
6. 与同批内容是否只是换角色、工具名、平台或标题？

## 锁定标题与34条迁移
用户锁定标题和V4.1提及的原始34条主标题均不得擅改。34条完整原文必须从对应源工作簿导入；本指导书不含完整清单，缺少工作簿时不得虚构或补写。改动应写入新候选字段并单独确认。

## 确认板
候选ID｜平台｜业务线｜受众/共同任务｜用户问题｜观看回报｜营销入口｜证据状态｜商业承接｜同批差异｜风险｜保留/修改/淘汰。用户确认前不输出完整脚本和完整执行表，除非用户明确锁定或授权直接执行。
