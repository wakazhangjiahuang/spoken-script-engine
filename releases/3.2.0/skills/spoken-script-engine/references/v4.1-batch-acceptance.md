# V4.1批量生产与逐条验收

## 计数口径
- `Topic_ID`：跨平台共享的选题主记录。
- `Script_ID`：某个平台的一篇完整口播稿。同一Topic在三平台有三个Script_ID。
- `Shot_ID`：一镜/一执行段一个ID。
- 100个Topic、100篇平台稿、100个Topic各自生成三平台版本不是同一数量，必须在`batch_manifest`中明确`expected_topics`、`expected_scripts`和`expected_by_platform`。
- 完整口播稿必须逐字可朗读；提纲、正文摘要、拍摄备注不能冒充完整稿。

## 批次节奏
样板10条 → 第一批10条 → 第二批20条 → 第三批30条 → 第四批30条。样板覆盖A/B/C业务线、三平台、不同受众和营销入口；未通过不扩批。

## 100分评分
八维权重：用户需求/受众15；主副标题/点击理由15；黄金开场/3–8秒承接15；正文故事/方法/价值兑现20；事实证据/可信度10；平台原生表达10；Calling/评论转化10；真人自然度/原创性5。每维0–5分，折算`score/5*weight`。每项附原文引用和理由，模型不得自评后自行放行。

- 85–100：强候选；
- 75–84：可发布候选；
- 70–74：必须二次打磨；
- <70：退回重写；
- 任一硬门禁失败：无论总分均禁止放行。

70分是编辑底线，不等于可发布；75分才进入候选。分数不预测流量、点击或成交。批次不得以平均分放行，逐条检查100%。

## 硬门禁
facts、promise_payoff、proof、platform、marketing、human_voice、direction、raw_first8、eight_deliverables。每个门禁必须有通过/失败、理由和证据引用。硬门禁失败即BLOCKED。

## 外部验证状态
真人朗读、目标用户盲读、发布效果分别记录。目标用户盲读建议3–5人；若宣称100条全部通过用户理解验证，100条都必须逐条盲测。未做标NOT_RUN/VALIDATION_PENDING。文本审查通过不能写成发布效果已验证。

## 批次状态
所有Script_ID必须一一对应；平台数量和预期数量必须一致；近似内容由语义评审识别并处理。任一条FAIL/REVISE/BLOCKED，整批不能标PASS；有未执行的真人/盲读/外部独立验证则标VALIDATION_PENDING。
