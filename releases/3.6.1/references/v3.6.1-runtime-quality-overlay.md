# v3.6.1 Runtime Quality Overlay｜理解—决策—生成—验证

## 版本范围

这是v3.6.0的闭环修复层。保留旧版知识资产、业务领域和AI视频/插画专用验证器。新入口`run_pipeline_v3_6_1.py`调用v3.6.0原入口的既有门禁，再追加v3.6.1四层验证；旧入口仅作兼容基线，不作为正式发布入口。

## 1. Understand：Source → Fact

- `source-manifest.json`是原始文件清单；每个源文件有运行目录相对路径、原始SHA256和文件名。
- `source_inventory.checked_assets[]`逐项绑定source manifest文件、哈希、原文定位、引用和实际读取状态。
- `fact_evidence[]`将Fact_ID绑定来源资产、原文位置、原文引用及文件SHA。
- DOCX/XLSX/TXT/CSV/JSON/Markdown/PDF尝试机器抽取；图片、视频、音频等非文本源必须附提取文本/证据文件、提取方法、原始SHA和精确定位。
- `provided`/`verified`事实没有原始证据则阻断；`inference`必须有父事实；假设/未知/未运行不得升格。

## 2. Decide：Candidate Competition → Sealed Decision

`marketing_entry_competition`至少3个候选，候选间至少3种不同入口类型；目标用户、需求、hook、click_reason、payoff、证据、交付、商业价值、风险、反证均需填写。每个未选候选有否决理由；只允许一个选中候选。计划必须绑定selected_candidate_id。

## 3. Generate：Mode Narrative Map → Spoken Script

每篇脚本将`content_mode`和`selected_entry_candidate_id`绑定计划。`narrative_map.stages[]`逐项引用真实口播台词；每个模式的必需阶段不可缺失。`claim_evidence[]`将实际spoken_claim_quote绑定fact_id、source_asset_id、source_file、SHA、locator及source_quote。封面、开场、桥接、Calling和平台适配必须绑定真实成品。

## 4. Verify：15 criteria + independent + external

`delivery_acceptance`必须每篇15个唯一标准ID。PASS有实际台词/证据引用和理由；NOT_APPLICABLE只允许在适用范围内并说明理由。任何FAIL阻断，PENDING保持待验证。

`reviewer_attestation`绑定评审者、生成者、独立会话、模型/人工身份、blind packet、review evidence、batch SHA、decision SHA和source manifest SHA。盲审包不得含评分。评审证据文件和哈希必须真实存在并匹配。

`external_validation`按Script_ID记录真人朗读、目标用户盲读、素材授权和平台结果。盲读3–5人，主题理解率≥80%，价值理解率≥60%。发布数据必须来自真实平台导出/记录，保留帖子ID、URL、发布时间、采集时间、可用指标、原始数据和SHA。

## 状态定义

- BLOCKED：硬门禁失败、来源链断裂、评审凭证无效或某项FAIL。
- VALIDATION_PENDING：编辑/结构门禁通过，但真人/盲读/授权/真实发布数据未全部完成。
- PASS：15项逐稿标准、独立评审和全部要求的外部验证均有证据通过。

平均分不参与放行。自动化只核验契约和证据一致性，不证明市场因果或平台表现。
