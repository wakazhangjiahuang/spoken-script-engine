# spoken-script-engine v3.5.0｜内容兑现与专业演示门禁

## 本次只修已有生产链的四个断点

1. **受众与需求不再重做，但必须形成可审计的内容契约。** 现有V4.1/V2.0已定义受众、共同任务和核心需求；本版只要求每条计划把它们绑定到本篇的点击理由、观看回报、证据计划和专业判断。
2. **专业决策不再止于字段与口播锚点。** 每篇增加一个可听见、可看见的worked example：具体输入、判断标准、前后状态、可观察变化和可迁移规则。
3. **Calling不再只检查有无行动。** 必须形成一个行动、行动理由和用户奖励；纯关注/点赞/评论/收藏请求不能充当价值交换。
4. **评分不再让关键短板被总分掩盖。** 核心维度至少4/5，其余至少3/5；总分仍沿用V4.1/V2.0原rubric，硬门禁一票否决。

## 1. 计划阶段：复用现有需求，补齐内容契约

每条`decision.selected[]`保留原有`audience_need_ref`，并在`content_contract`中提供：
- `target_audience`、`shared_task`、必要时的`shared_task_reason`；
- `why_now`、`click_reason`、`promised_payoff`；
- `proof_plan`、`decision_criteria`、`transferable_value`、`next_value`；
- `entry_competition`（至少三个不同机制的入口）、`selected_entry_id`、`selection_reason`、`counterargument`、`counterevidence`。

不得把多角色机械合并，也不得机械限定为单岗位；多个角色只有在共同任务真实一致时才共读。标题入口可来自商业结果、产品决策、趋势/调查、图鉴、审美研究、人物故事或工作流变化，不强制套一种利益句式。

## 2. 脚本阶段：worked example必须落在口播正文

每篇`professional_decision`新增`worked_example`：

```json
{
  "input_snapshot": "本篇实际处理的具体输入或明确模拟输入",
  "decision_criterion": "决定方案取舍的可观察标准",
  "before_state": "处理前可观察状态",
  "after_state": "应用选择后的可观察状态",
  "observable_delta": "前后真正发生的变化",
  "transfer_rule": "观众可复用的条件规则",
  "spoken_anchor": {"segment_id": "BODY-01", "quote": "正文中说出选择与理由的原句"},
  "result_anchor": {"segment_id": "BODY-02", "quote": "正文中说出可观察变化的原句"},
  "transfer_anchor": {"segment_id": "BODY-03", "quote": "正文中说出迁移规则的原句"}
}
```

锚点必须逐字存在于对应正文段落。只写“先确认需求”“按实际情况调整”“注意细节”或步骤清单，不构成专业演示。前后状态必须可区分；变化不能只写“更好/更专业/提升质量”。

## 3. 点击到兑现的跨字段链

每篇必须有：
- `cover_main`、`cover_sub`；
- `first_8_progression`：`hook_segment_id`、`bridge_segment_id`、`bridge_new_information`、`reason_to_continue`；
- `content_contract.body_payoff_anchor`：正文实际兑现承诺的原句。

3–8秒必须含有可定位的新信息，不是0–3秒换词复述。主副标题与主画面共同构成点击理由，不能脱离Title Guide V4强制使用固定句式。

## 4. Calling价值交换

每篇增加`calling_value_exchange`：

```json
{
  "action": "一个主要行动",
  "reason": "用户为什么现在做",
  "reward": "用户完成后得到的具体价值",
  "segment_id": "CTA-01",
  "quote": "Calling口播中的完整原句"
}
```

行动、理由、奖励必须与实际CTA段一致。收藏清单、领取模板、提交资料、预约诊断等可以成立，但必须说清用户会得到什么；只要求关注、点赞、评论或私信不通过。

## 5. 评分与审查

核心维度至少4/5：
- AI视频：`audience_need`、`cover_click_reason`、`opening_bridge`、`body_payoff`、`cta_comment`；
- 插画：`audience_and_task`、`entry_and_click_reason`、`first_8_seconds`、`professional_judgment_and_payoff`、`calling_and_action`。

其余维度至少3/5。总分仍沿用AI视频V4.1和插画V2.0原权重；70为最低编辑线，80为内部目标。任何硬门禁失败不能用总分补偿。

每篇review新增：
- `worked_example_review`：检查输入是否具体、标准是否真正应用、前后变化是否可观察、迁移规则是否成立；
- `click_chain_review`：检查目标用户是否认领价值、承诺是否具体、正文是否兑现；
- `calling_value_review`：检查是否只有一个行动、奖励是否清楚、是否不只是索取互动。

评审必须引用实际脚本中的对应原句。AI视频继续执行V4.1的review routing；插画继续执行V2.0的独立reviewer与证据文件检查。同一模型不同角色不算独立评审。

## 6. 负向回归

`assets/qa/negative-six-script-regression-v2.jsonl`保存此前六篇30分稿的原始标题、前8秒、正文和Calling片段，身份固定为`NEGATIVE_REGRESSION_ONLY`，不得作为正向few-shot。

每次升级必须运行`tests/test_content_quality_v350.py`，证明六篇均被新门禁阻断，并覆盖：源需求不绑定、选题入口同义、无worked example、变化没有口播锚点、CTA无价值交换、核心评分低于4/5等失败情形。

## 7. 唯一入口与验证边界

唯一入口：`scripts/run_pipeline_v3_5.py`。它在v3.4.2既有源资料加载、需求绑定、锁定字段、BENCHMARK治理和领域验证器之上增加本版内容兑现门禁。不得绕过新入口直接调用旧版脚本导出。

程序可证明来源引用、字段锚点、前后状态、Calling契约、评分门槛和回归测试执行；不能证明真实用户一定点击、停留、收藏或成交。目标用户盲读、真人试读和平台实测必须保留真实证据与状态，未执行不得标PASS。
