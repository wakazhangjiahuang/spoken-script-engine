# 口播稿引擎 v2.0.0 升级复核

本次依据用户确认的通用指导手册 v2.0 和三平台18篇精修样表 v4.0。原件与逐表提取结果保存在 assets/kb-snapshot/sources/approved，provenance.json记录原件哈希、用途和事实边界。早期TXT在当前附件中未独立重读，不伪称已逐字核验。

## 升级前先回答的四个问题

1. 顶尖执行者会先建立可失败的验收合同，再找反例；区分内容合格、可拍、可发布与已产生商业效果，防止漂亮样稿被当作转化证据。
2. 从用户原始请求、原始业务材料、已确认手册HTML和样表XLSX起步。拆出原句、表格位置和事实来源，再核对旧代码、schema与GitHub固定版本；不以旧助手总结替代原件。
3. 方法是逐阶段合同、来源矩阵、候选比较、四维选型评分、六维编辑复审、七项否决门禁、留出任务测试与故意构造失败输入。工具为GitHub固定commit读取、SHA256、JSON Schema、Python校验器、openpyxl回读、实际表格渲染与独立审阅。
4. 可检查的外部凭据是原件哈希、Git提交、反例测试、独立内容评审和导出回读。真正的传播/转化效果还需目标用户盲测、同行检查、新手试拍及平台后台对照；本次未做的明确记为未运行。

## 具体改动与理由

|层级|旧问题|v2.0落地|
|---|---|---|
|完整链路|指令、schema、量规和表格版本不一致|五阶段执行，十二环节合同；每环节有输入、选择、评分/硬约束、产物、失败出口|
|需求与事实|历史样稿容易被当本轮经历|原始请求必留；素材状态、事实、示例和待核验分开；收据绑定原件、简报、资产与方案|
|检索|仅按目的挑少量固定公式，跨行业匹配不清|任务×目的×证据先筛；再按词排序；语义须编辑复核；保留弃选理由与匹配边界|
|选型|只有最后评分，缺少写前判据|四维受众/证据/平台/行动评分；每项≥3，总分≥80；方案封存后才成稿|
|创作|旧评分不能对齐已确认手册|黄金三秒、悬念、专业、审美、利他、Calling按15/15/25/15/15/15；引用指定段落评分|
|平台|把机制建议说成算法规则的风险|官方规则、机制资料、创作假设、待核验四层；账号权限与当次规则单独核对|
|导演|台词、素材与镜头不一定可执行|逐段素材ID、状态、动作、字幕、切点、静默留时、备选方案；估读与真人试读分开|
|交付|样表与生产导出不一致|总览＋各平台1表＋拍摄卡；三平台5表；分段与全文同源，回读逐字校验|
|反馈|采纳、效果、经验晋级可能混用|品牌隔离、去重、待同步/已回读；采纳不等于有效，未验证不升级为规律|

## 本次发现并修复的真实缺陷

独立代码审查复现了两个原本可通过验证的问题：重复F16候选绕过无证据筛选；空阶段文件映射绕过原始请求/方案封存。现已先去重筛选、再在方案层复核证据；强制intake/plan/draft/revision次序与必需文件，绑定原件和知识快照。新增负例测试防止复发。

## 验收边界

50项自动测试通过，包括单篇3表与三平台18篇5表、108段拍摄台词回读；这些测试的合成分数不是内容质量证据。总览、口播列、拍摄卡已实际渲染检查。具体留出内容评审见 evals/upgrade-v2.0.0.json。

官方规则核验记录在知识库rules/current-verification.jsonl；仅检索摘要或访问不完整的材料保留PARTIAL。没有公开固定算法权重，不生成所谓平台算法分。程序不证明真人身份、私下思考顺序或复审声明真实性，内容和素材真实性必须由实际执行者核对。
