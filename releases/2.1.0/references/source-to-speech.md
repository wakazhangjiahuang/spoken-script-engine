# 从资产到台词｜2.1生产合同

## 先选观众问题，再选表达

同一作品可以服务接单经验、产品选型、技法教程、开发幕后或合作咨询。先用一句观众原问题锁定本篇；不能把“笔刷”自动译成技法教程，也不能把“商业价值”自动译成收入故事。

- 接单/商业案例：观众想知道机会怎么来、客户为什么选、自己能借鉴哪一步。真实结果可作入口，正文必须交付与该结果有关的选择或行动；不能转进一大段线条颜色描述。
- 技法/工具：观众想知道自己能完成什么、怎么验证。给实际动作和检查方法；不用“客户买单/避免返工”给无证的画法建议贴商业标签。
- 幕后/能力：观众想看到当前任务中的具体困难与选择。展示问题、处理、依据；不把流程名堆砌当专业证明。
- 合作咨询：观众想知道你能解决自己的什么问题、怎样开始。先证明一项相关能力，再收最少项目背景；不泛问“喜欢哪款”。

一条稿选一个主要受众、原问题、可带走结果和主行动。点赞、收藏、分享是价值发生后的可能行为，不必每种都喊；有可复查清单才有收藏理由，有团队共同决策才有转述理由。没有自然理由，结尾可以完成任务，不硬求互动。

## 联动读取，禁止分头拼接

`asset-pack.json`含原公式记录、口播机制、标题原行、平台应用、完整编辑样例及must_read_guidance正文。真正读取准备采用的记录和完整样例；记录存在或哈希正确不能替代读过并用对。

先查同任务、同观众、同证据的样例；没有完全适配时可选结构参照，明示mismatch和不迁移部分。既有18篇主要面向商业插画服务的商家，不能仅因“插画”二字就当作设计师接单样板。五步截图只认可其结构；金额/客户/渠道/Calling原句都不是新任务事实或固定用词。

正文公式按证据和问题选择，不为数量强制每篇换公式。标题原行只提供吸引机制，按所选hook_id取对应分组；不能由标题推导现实收益。原式若弱或不适配，应说明不采用的原因，换机制；禁止为了“遵循公式”生硬填词。

方案`source_recipe`固定三项原文：hook_template=口播机制spoken_structure、body_structure=正文structure、calling_template=行动pattern。example包含asset_id/record_sha256/source_quote/match_level/task_match或structure_only/transfer/non_transfer/mismatch。title包含status=matched或no_match，以及所选标题条目的title_id/source_line/original_line/retained/discarded；no_match须说明原因。事实与素材写proof_basis，逐项resource_id/fact_ids/scope；订单案例不能借一张效果图证明金额、渠道或客户评价。

方案`audience_contract`含question/payoff/motivation/route/primary_action/action_reason；动作取comment/save/share/follow/inquiry/purchase/apply/none。inquiry/purchase目标不能偷偷退回泛评论。

## 写出来，并映射回原式

每稿`composition`：
- audience_question与primary_action必须与方案一致。
- hook_slots按所选机制variables的`|`顺序逐项给slot/segment_id/surface/quote。surface为speech/visual/subtitle；首句和首镜可分担信息，锚点必须在前两段真实内容中。
- body_beats按所选正文structure的`→`顺序逐项给beat/segment_id/quote，全部在Calling前的真实口播中；结果前置允许先出现结果，但后文仍解释结果如何形成。复杂取舍不能只写“我做了沟通→调笔刷→画图”。
- payoff/takeaway/calling各给segment_id/quote，必须是实际说出的原句。payoff回答开场问题，takeaway让观众能复制一个动作、选择或判据；制作备注不补台词。
- claim_links逐项连本轮事实。收益/成交/客户/时间等具体主张须覆盖，不能用“待核实后使用”留在完整口播里。没有事实则换开头；若核心信息缺失，单列待补，不把半成品当成完整稿。

对应关系只证明可核对。独立编辑还要判断：变量填得是否有吸引理由，公式节点是否讲了实质内容，观众问题是否被回答。解释写得再好，也不能抵消不好听、无用或没兑现的台词。

## 本轮失败的否决样例

| 实际失败原句/现象 | 否决原因 | 必须改变的内容 |
|---|---|---|
| “想接复古风单？线条先改！”后只教断线叠色 | 收益入口跳到技法，接单问题没回答 | 接单稿解释客户判断或作品交付；技法稿直接承诺具体技法成果 |
| “我把这张上传的原稿当作观察样本” | 助手分析腔进入台词 | 对着观众指具体对象、讲一个判断 |
| “对应到实际产品，我会这样判断”＋产品列表 | 备注式过渡，缺少观众下一步 | 给这个受众当前能执行的一步及检查结果 |
| “评论『接单』，我下一条……” | 行动主要服务作者、把价值延期 | 本片先兑现，再邀请一个具体问题或适配信息；也可不求评论 |
| “靠这套复古画风，我赚了500美刀！”＋“核实后使用” | 收益主张无当次事实支持，留编辑占位 | 删收益入口或补本轮原证，不靠免责声明修补 |
| 24篇正文不变，只换受众词 | 策略没进入正文 | 改观众问题、信息和证据顺序；事实少时减少案例型选题并用真实方法/比较内容补足 |

这些是反例，不是行业黑名单。不能把每篇都写成“不要只……”，也不能把本轮笔刷、300美元和Instagram写入全行业固定规则。

## 独立编辑如何否决

不给生产评分，逐篇只看原请求、原件、封存方案、资产原文和台词：
1. 遮住标题与备注，只听开头，能否指出谁为什么愿意继续？只自夸/空问句/加个“接单”不成立。
2. 遮住所有“用户利益”解释，只读正文，能否复述本篇承诺的具体收获？收获不能由编辑替观众补脑。
3. 将源公式逐节点与实际原句对照，标欠缺、错用或适配；同词不等于同机制。
4. 结尾所要的信息能否推动一个对观众有价值的下一步？不能只填一个关键词让作者知道拍什么。
5. 同批去掉开头和结尾比较正文，是否仍有实质区别？相似度检测只抓近重复，语义同质化仍由编辑否决。

review新增composition_checks，每篇逐项audience_payoff/source_fidelity/action_motive/fact_scope，带passed/segment_id/quote/reason；source_comparison引用正文asset_id与structure原文并写deviation_judgment。失败先改对应台词，再重新绑定评审，不靠抬分。

## 小批确认与实际验证

批量先写不同内容路线的1–2篇内部试稿，在同次任务内复核并修复后再扩写；已有授权不为这个步骤另加用户确认。数据或案例不足时明确限制，不换词凑同类故事。

机械检查、独立模型编辑、目标用户盲测、真人试读、实际发布结果分别记录。审稿通过只说明当前编辑判断。发布测试用相同受众/主题/素材、一次只改一个变量；记录测试窗口、曝光分母和基线，不能由公式名或编辑高分宣称“爆款”。
