# 受众、正文与 Calling

先写一句选题诊断：「谁正在做哪件事，卡在哪个决定，这条片让他能做什么」。每篇只承担一个问题。锁定原主题及阶段，明确平台、受众身份、真实场景、问题、内容目标、可用素材和需要核验的声明。区分原件、官方、用户提供事实、二手总结、假设、实测与推断。关键数字、产品能力或渠道未确认时改用可复现的方法、带标记的示例或更小承诺。只有影响对象、主张或主要行动且无法安全降级时才问用户。

## 价值翻译与兑现

功能 → 当前做法与阻力 → 具体动作变化 → 客户能观察的收益 → 条件与边界。示例：系统归档、汇总并列出异常 → 员工先核对异常项 → 最终报价由员工确认。没有工时实测就不报节省百分比；示例不是客户证言。

根据目的选择一个正文推进法。教程用问题、原因、操作、复核。案例用约束、选择、过程、证据和边界。种草用场景、对照标准、演示和适配条件。企业服务用客户决策、旧做法阻力、服务介入边界、可检查交付。开发记录用已发生事件、关键取舍、已做与待做。专业知识用常见误判、机制、可复用判断。每段新增一个判断、动作、证据或必要边界，让第一段正文出现价值线索，最后一段正文兑现承诺。普通话试读，难念的并列、术语、字母和数字换成用户熟悉的词或留足停顿。

## 阶段与行动

| 决策阶段 | 旧表字段兼容值 | 观众理由与行动设计 |
| --- | --- | --- |
| 认知 | 认知 | 停留靠关联，继续看靠已露出的价值，给一个检查、经历提问或可收藏的小方法 |
| 兴趣 | 认知 | 让用户看懂新选择，给可复做的演示或有明确对象的分享理由 |
| 信任 | 考虑 | 展示证据、责任和条件，邀请观众说明自己遇到的例外 |
| 考虑 | 考虑 | 给决策清单和适配条件，区分需求咨询和一般互动 |
| 咨询/转化 | 行动 | 保留咨询目的，明确产品/场景、一个卡点和下一步，渠道另核验 |
| 复购与传播 | 使用 | 给复用、维护、分享的现实理由，或收集使用中的下一个问题 |

旧合同锁的是表字段值。细阶段用可选字段记录，并且必须与旧字段相符。已锁定更细阶段时，不移动到同一旧字段的另一细阶段。

为稿件记录停留理由、继续观看理由和兑现结果。点赞靠观点或共鸣，收藏靠复用，转发靠接收者价值，关注靠明确的持续方向，评论靠真实参与理由，咨询靠清楚价值和匹配需求。每篇只选一个主动作，不需要把其他动作念出来。结尾必须能找到唯一的主请求。经验征集问一个具体场景，问题征集问最难判断的一步，A/B 让用户说条件，需求识别允许匿名概括。资料引导只用真实存在且当前可获取的补充，完整价值留在正片。业务承接走已核验的站内渠道。账号能力未知时保留业务咨询目的和下一步范围，用内容相关需求讨论承接，标记渠道/准入待核验；不降成普通偏好投票，禁止私联口令、奖赏换互动和刻意卡住答案。

评论型 Calling 要产生可用线索。记录准备观察的匿名信号，例如「缺负责人」「截止日模糊」，并写出它如何变成下一条问题或演示。没看到真实评论时标待观察，不写成既有反馈。无需在口播许诺一定会制作下一条。

## 取舍类开发记录
用户要讲开发取舍时，说明当前先承接哪一步、仍要付出什么可观察代价、哪一步未完成；不能用重复“已做/待做”替代取舍解释。可从用户已提供的功能语义解释影响，例如手动入口仍需人主动操作；这类解释不等于已知团队动机。没有原始记录，不补工时、难度、预算或客户压力；将开头承诺收在可用证据内，并把未确认的研发原因留在内部缺口备注。
