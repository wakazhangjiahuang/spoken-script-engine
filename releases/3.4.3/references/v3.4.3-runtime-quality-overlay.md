# spoken-script-engine v3.4.3｜源资料进入生产链路与专业决策验收

## 本次只修三个断点，不重建受众和选题库

1. **资料存在不等于生成时已读取。** 领域指导书必须以全文进入 `asset-pack.must_read_guidance`，并带 `source_asset_id`、原始路径和SHA；只校验文件存在或列出文件名不算读取。
2. **字段存在不等于专业决策成立。** 选题计划先绑定已有指导书中的原始需求句；脚本沿用同一引用。每篇必须在口播正文中讲清具体输入、约束、至少两个真实备选、取舍、理由、适用边界和用户动作。
3. **评分存在不等于质量过关。** 评分引用必须锚定对应字段/镜头；插画每维最低3/5且总分不低于70；硬门禁失败一票否决。AI视频继续使用V4.1正式验证器，不得以轻量字段检查替代。

## 生产前的源需求绑定

每个 `decision.selected[]` 必须有 `audience_need_ref`：
`source_asset_id`、`source_locator`、`source_quote`。

- `source_asset_id` 必须是当前领域指导书ID，不得用历史样例ID替代。
- `source_quote` 必须逐字存在于已加载的原始指导书文本中。
- `source_locator` 必须能在同一来源中定位。
- 脚本 `professional_decision.audience_need_ref` 必须与批准计划完全一致。
- 不重新泛化受众，不把身份标签改写成需求，不为凑选题新增画像。

## 正文专业决策单元

每篇都要让观众听到，而不是只写在备注中：
- 具体输入/材料；
- 至少两个不同方案及各自代价；
- 当前约束下选择什么、放弃什么；
- 为什么这样选；
- 哪些情况适用、哪些情况不适用；
- 观众下一步可以做什么。

`spoken_anchors` 必须分别定位选择、被否决方案、理由、适用边界和用户动作。只用一句“先确认需求”“要看实际情况”不能通过。

模拟案例必须在口播正文明确说“模拟/示意/假设情境/虚构情境”，并使用 `SIMULATED:` 证据引用；不能把模拟过程写成真实客户结果。

## 质量验收

- AI视频：沿用V4.1八维权重、候选角度竞争、review routing、hard gates、字段级原文锚定与70分编辑底线；新增每维最低3/5及专业决策审查。
- 插画：沿用V2.0八维权重、锁定字段、事实/权利、平台、专业价值、04/05映射硬门禁；新增每维最低3/5、字段/镜头级评分锚点和源需求独立复核。
- 生成者不得为自己的稿件提供独立PASS。插画reviewer必须为human或separate_model；AI视频沿用V4.1 separate_model/human review routing。
- 真人试读、目标用户盲读、授权与平台表现没有实际证据时，保持`VALIDATION_PENDING`或`PUBLISH_HOLD`。

## 唯一执行入口

所有阶段统一使用 `scripts/run_pipeline_v3_4.py`：`intake → plan → draft → validate → export`。
该入口在intake后核对当前指导书全文是否进入资产包；plan时核对需求来源；draft后核对每篇专业决策和口播锚点；validate/export时再核对独立审查、逐维评分和硬门禁。

不得直接用旧`run_pipeline.py`或`run_pipeline_v3.py`绕过v3.4.3源资料和内容门禁。AI视频最终发布验证如需真人/盲读全通过，另加`--require-v41-full-validation`。

## 验证边界

程序能证明文件读取、引用存在、字段对应、评分计算、门禁执行和文件哈希；不能证明真实观众一定点击、观看或成交。吸引力和市场效果仍需目标用户盲读、受控对照与真实发布数据验证。
