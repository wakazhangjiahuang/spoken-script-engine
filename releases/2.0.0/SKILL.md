# 口播稿引擎 v2.0.0

把用户认可的通用手册转为可执行判断，把三平台18篇样例作为写作参照。方法通用，案例有行业；不得把插画ABC、客户国别、时间、旧评分或未测效果迁移成新任务事实。默认所选平台各3篇，未选平台默认三平台；明确篇数优先，1篇就做1篇、每平台6篇就做18篇。明确“总计N篇”时先给出合理平台分配，不误解为每平台N篇。保留锁定主题、真实创业团队口吻和有效专业判断。

## 起点与质量合同

先读[逐环节合同](references/stage-contract.md)，再按[执行字段](references/execution-v1.6.md)整理需求。写清：“谁在做什么，卡在哪个决定，听完能判断什么”。一篇一个主要受众、决策和业务目的。任务轴为诊断/纠偏/教程/案例/比较/异议/规划/留存；平台轴决定入口、证据、节奏与行动，不把平台等同固定受众。

原始请求与本轮原件优先。事实、推断、示例、待核验分开；缺证据收小主张或明确示例，不编客户冲突、返工、评价、成交和收益。先决定首镜和证据可如何拍，再写台词。

唯一评分来源：assets/kb-snapshot/rubrics/quality.json。六项权重依次为15/15/25/15/15/15；每项0–4且≥3，加权≥80；事实、开场兑现、证据、平台、营销、口语、可拍七项门禁不能用总分抵消。这是编辑门槛，不是效果保证。

## 五阶段生产，十二环节交接

使用技能目录中的 scripts/run_pipeline.py；RUN是本次新目录。先读schemas，不猜字段。内部JSON不要求用户填写，不额外交付繁杂审计表。

1. **Intake｜需求、事实与检索**：保存原始请求request.txt，运行 `intake --run RUN --input brief.json --request request.txt`，每份附件追加`--source 路径`。按[知识协议](references/github-and-memory.md)获取固定版本；可传`--kb 已校验缓存`，RUN复制并绑定该知识版本。检索依次判断内容任务、业务目的、证据可用性，再按主题排序。读取通用方法、标题来源、口播机制、正文公式、Calling、平台策略。approved-examples是已认可编辑样稿；real_cases是可核验业务案例；published_scripts是已发布内容，三个数量分开。没有匹配就如实报告，不强塞异业故事。
2. **Plan｜比较、评分与封存**：读asset-pack.json，每平台选N个方案及至少1个弃选。按selection.json对受众相关、证据适配、平台适配、行动适配逐项0–4评分并写具体理由；选中每项≥3、总分≥80。记录买家决定、真实张力、取舍、证据、兑现和行动。asset_refs绑定真实ID/哈希及本次用法，标题公式不冒充口播机制。执行 `plan --run RUN --input decision.json` 成功后才写成稿。改目标/事实/机制须新RUN。
3. **Draft｜六项创作与导演**：生成engine_version=2.0.0的batch。每稿按hook、suspense、context、judgment、value、calling组织，正文可分多个判断段。第一段≤3秒，前两段累计≤8秒；按可读字速和静默操作留时核算，不挤长句冒充黄金三秒。首个判断及时兑现开场。正文说明选什么、为什么、放弃什么、证据在哪里、何时适用；将能力翻译成观众能用的判据。审美表达落在层级、具体、克制和一致，非视觉行业不套颜色/笔刷词。Calling只留一个主动作，延续已证明价值。台词不能带“案例：/专业判断：/观众所得：”制作标签。逐段绑定素材、镜头动作、字幕、切点和替代；available/planned/unavailable分开。[开场](references/hook-workshop.md)、[自然口语](references/natural-voice.md)、[导演](references/director-workflow.md)。执行 `draft --run RUN --input batch.json`。
4. **Independent review｜独立复审与定向返修**：把原始请求/原件、封存方案、资产包、版本稿、六项量规交给独立线程或人工，不给生产评分或预期结论。按[复审标准](references/decision-and-qa.md)引用真实段落与原句，各维独立判断；有问题允许不通过。最多两次定向返修，旧稿不覆盖，新版本重新绑定评审。没有独立执行条件时交明确待审草稿，不能伪造复审通过。
5. **Validate & export｜校验、交付与后续**：执行 `validate --run RUN --input RUN/batch-v1.json --review review.json --output validation.json`；通过后同参数改用export并将output设为XLSX。正式唯一[表格合同](references/task-contract.md)：总览＋所选平台各一表＋拍摄执行卡；三平台为5表。平台稿能分段看也能整篇复制，执行卡逐句对应。导出后逐字回读；实际看预览，未看不称视觉验收。真人试读、素材和规则不足时保留明确未完成状态；不阻止诚实编辑交付，也不宣称发布就绪。

## 后续环节与效率

- **平台核验**：[发布检查](references/platform-release-check.md)。官方条文/机制研究/创作假设/待核验分层；核对当次来源、日期、范围与账号权限，不编算法权重。小红书给可复看判据，抖音首镜与快速证据，视频号给合作适配依据，均为创作策略。跨平台必须改变证据组织或推理路径，不只改口吻。
- **真实验证**：用户盲测能否认出任务与复述判据；同行检查专业依据；新手按表试拍；平台同目标单变量测试，记录样本/分母/窗口/基线。未运行一律NOT_RUN，不用高分证明效果。
- **知识回流**：只有授权反馈才入库；事实更正、偏好、编辑采纳与实测表现分开，品牌隔离、去重、待同步与回读确认分开。新增方法须有适用条件与反例，不自动晋级官方规则。
- **控制成本**：一份简报、一份校验快照、一轮候选比较、批量生产、独立复审。只补查缺口和返修失败段；如实记录检索耗时、候选量和返修数。不以增加公式/页面/工作表充当深度。
- **边界**：收据证明记录顺序和文件绑定，不证明私下推理顺序或审稿者身份。自动校验不替代语义审阅。只在用户授权范围保存，不自动发布、不向他人发送消息。
