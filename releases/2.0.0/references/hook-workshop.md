# 黄金三秒｜口语化与选用

常规读取 asset-pack.assets 中 source_path=shared/spoken-hooks.jsonl 的记录，同时对照所选平台的hooks与formula-applications。H301–H317 以触发理由、所需证据和正文兑现来区分。同一个机制的情绪、语气、数字、问句或身份变体仍归同一 ID。旧 H01–H12 用于历史稿回读与旧远端缓存兼容。对照如「结果先看」交付现有产物，「现场做」以动作当场验证，「同条件对照」必须交付两个可比状态。「过程现场」顺着一个现场节点走，「中途事件」聚焦故事中的决策。别为了覆盖更多类别把一个机制重复计数。

## 从标题转成第一句话

1. 先拆标题的对象、具体场景、问题、承诺、暗含前提，记来源 ID。删掉封面排版、标签、数字占位、情绪夸张、暗示权威和没有证据的第一人称。
2. 判断观众停下的原因，并从库中找能用真实证据兑现的一种机制。合并仅语气、数字、疑问式或关键词不同的同义项。原条目逐项归入「转用／合并／淘汰」，有来源定位和原因才算完成导入。
3. 按说话顺序重写，让对象、动作或可见的矛盾先出现，口播和首镜可以分担信息。开场的第一拍尽快交代关联，通常以约前三秒为检查点；结合试读、停顿、画面和语速调整，不固定总时长、字数或信息节拍。
4. 写至少两种机制不同的开头。主开头是第一段真实口播，备选可接同一正文且用同一证据；需要换正文才能兑现的开头应另建候选稿。记录首镜、承诺、正文兑现段和为什么选择。首个价值线索尽早交付，关键答案在 Calling 前讲完。
5. 不沿用来源示例原句。常见误区是对谁都喊、首镜和首句讲两件事、拖住答案、把演示当客户成果。数值和对比写明条件与来源，不能从候选标题推导受众事实。
