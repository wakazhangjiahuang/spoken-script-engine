# 口播稿引擎 3.8.0

执行《口播稿引擎完整系统指导书 V3》决策与营销表达专项。本包 3.8.0 使用既有 3.6.1 生产校验核心，正式入口为 `scripts/run_pipeline_v3_6_1.py`。

1. **理解并锁定资料。** 从本轮原件、产品或项目、客户当前决定与证据起步。读取 [V3 执行合同](references/decision-workflow-v3.md) 和 [知识检索](references/knowledge-retrieval.md)。先识别客户实际购买的服务，再选业务适配器和平台。原始卖点、客户体验、比较与服务证据为可选输入，按事实、适用范围及授权消化。
2. **先证明为什么值得选。** 分开做品类比较和具体项目比较。购买理由使用 `ADVANTAGE_VERIFIED`、`FIT_SUPPORTED` 或 `INFO_ONLY`。无授权、矛盾来源、缺证强推进入阻断或定点改题。每篇比较至少三个实质不同的入口。胜出入口须把原始特征转成条件明确的能力、差异或适配、客户收益、证据、购买理由和营销表达。系列按客户问题与观看回报去重。
3. **A 只交选题确认板。** 用 `intake --mode A --run-context` 和 `proposal`。板中展示目标客户、根本需求、品类及项目理由、胜出切入、标题和前八秒方向、正文兑现示例、证据、行动及风险。用户确认号后执行 `select`。本轮明确授权直接成稿时，同轮完成决策和交接。修改方向用新 A revision。
4. **B 继承封存的选择。** `intake --mode B --handoff` 后按 `plan → draft → validate → export` 执行。从确认的受众、证据、购因、入口、承诺、平台和行动生成九个字段。评论默认置顶或评论区。逐字保护整句或前缀锁，原始资料只读。证据冲突、承诺漂移或含义改变退到对应上游。阅读 [完整成稿与 15 项验收](references/full-production.md)。已有封存旧版运行用原路径续做。
5. **逐篇放行。** 三道关口分别看客户价值与购买理由、营销表达、正文兑现；九字段、原有十五项和领域审核全部逐篇验收。基于实际稿件和证据独立评审。真人试读、目标客户盲读、素材授权、发布结果按实际记录。通过结构检查仍需保留未完成的外部验证状态。按需产出 04/05、工作簿和回读清单。从真实平台与业务记录做发布后反馈。

AI视频V4.1、插画V2.0、Title Guide V4 与双标杆的既有领域校验继续按适用范围调用。封存的 v3.5.0、v3.5.1、v3.6.0 运行沿原入口复核。实际外部证据待取得时记录 `VALIDATION_PENDING`。
