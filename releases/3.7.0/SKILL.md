# 口播稿引擎 3.7.0

## 路由与交付

- **A 选题策划。** 用户说先提案或只要选题时，按本轮 Prompt 的目标、数量、锁定及交付深度执行。走 `intake --mode A` 和 `proposal`。交付实际提案，可含正文示范。用户可选择、修改或淘汰单篇。
- **B 成稿制作。** 用户确认篇目后，用 `select` 封存所选编号，再用 `intake --mode B --handoff` 开新 B 运行。直接成稿已获授权时，在同一轮完成选择和交接。已有正式封存运行按原路径续做。
- 已选题的受众、平台、客户决定、承诺、行动和锁定原文随交接保留。编辑只改授权字段。若证据结论改变或锁定与时长冲突，回到受影响的一篇。B 按请求交付完整稿、XLSX、04 真人拍摄卡或 05 H3 数字人卡。

正式入口为 `scripts/run_pipeline_v3_6_1.py`，包含 3.7.0 提案与选择路由。先读取 [A/B 执行](references/proposal-production.md)。B 另读 [完整成稿与 15 项验收](references/full-production.md)。参考中 3.6.1 为保留的验收核心。通过程序检查后仍须如实记录试读、盲读、授权和平台效果状态。

## 知识检索

按[知识检索接线](references/knowledge-retrieval.md)读取当前私有 GitHub 知识。启动 A 或直接成稿先匹配赛道、客户任务和平台。A 转 B 带入本轮固定的知识版本、条目与原件定位。

## 策划时实际做的事

1. 从本轮用户指令、作品、Brief、案例原件起步，明确服务对象、他要决定什么、证据支持到哪一步。用当前领域指南与合适的认可样例校准表达。保护原例与客户事实，案例素材的授权、推断和模拟边界按原规则办理。
2. 按本轮要求逐篇比较入口。候选写出可看的标题或承接句，配一个可展示的具体判断，再决定是否采用。比较客户问题、收益和正文答案。允许共享素材。首句或前缀被锁定时，在许可范围内做差异。
3. 用实际标题、前八秒、正文示范及 Calling 定点复核。把同义问题当同一题，把能否兑现和是否更吸引人分别判断。既有量规按阶段用。策划先看受众、入口、承接、取舍、事实、平台、行动和可读性。修改后检查原问题是否消失。审查时看稿件和证据，省略生成者自评。模型自查记录为编辑辅助，外部证据只按实际取得的材料登记。
