# 口播稿引擎 v3.6.1

**v3.6.1 是 v3.6.0 的定点闭环升级，不扩展业务范围。** 保留AI视频V4.1、2026-11-23团队制作手册、插画V2.0、Title Guide V4、双标杆、三平台知识库、既有受众与需求、原始工作簿、v3.5.0专业内容门禁及v3.5.1正式审查接线。只把「理解—决策—生成—验证」转化为实际执行门禁、原始证据链、逐篇15项验收和效果回流。

## 0. 完成定义：不能以“写过规则”代替“证明结果”

不得用“我已经理解/读取/检查/完成”作为证据。不得仅因字段存在、脚本已生成、模型自评高分、CI通过或平均分达标而宣布完成。

每个阶段必须产出可检查的原始材料、实际执行产物、精确引用、文件哈希、决策记录或独立验证记录。任何证据缺失必须标为 `NOT_RUN` / `VALIDATION_PENDING`；任何硬门禁失败必须阻断，不得由其他项目的高分补偿。

**四层主链：**

1. **理解：** 原始文件、用户需求、真实项目、目标用户、用户收益和证据来源可追溯。
2. **决策：** 至少比较三个真正不同的营销入口，评估吸引力、证据、兑现能力、商业价值及风险，保留否决理由。
3. **生成：** 把15项标准落实到实际封面、开场、正文、专业判断、Calling和平台成品；不同内容模式使用不同叙事组织。
4. **验证：** 绑定实际成品、原始来源、独立评审凭证、真人试读、目标用户盲读、授权证据和真实发布数据。

唯一执行入口：`scripts/run_pipeline_v3_6_1.py`。不得绕过入口直接调用旧版本导出器作为正式交付。

## 1. 第一层｜理解：先读原始材料，再决定讲什么

每次 intake 先读取本轮用户请求、附件、项目文件、指导书、样例、原始工作簿、产品/作品/订单/流程资料和制作资源，再形成 `source_inventory`。不得在材料盘点前先套故事模板。

每项材料至少记录：
- `asset_id`、原始文件名、运行目录内路径、原始文件SHA256；
- 实际读取状态、原文位置（页/段/表/Sheet/单元格/时间码/画面帧）；
- 可回到原始文件核对的原文引用；
- 非文本材料的提取方法、提取证据文件及其SHA256；
- 该材料支持哪些事实、主张或产品判断，不能支持什么。

每个 `provided` / `verified` 事实必须建立 `fact_evidence`：`fact_id → source_asset_id → source_file → source_sha256 → source_locator → source_quote`。脚本中的每个关键事实主张必须建立 `claim_evidence`，把实际口播句、事实ID、原始来源和原文引用连起来。推断必须列出父事实ID；假设、未知、未运行必须保持原状态。

对DOCX、XLSX、TXT、CSV、JSON、Markdown及可提取PDF执行原文抽取与引用匹配；图片、视频、音频等非文本资料必须附提取证据、方法、原始文件SHA及精确页码/时间码/帧定位。无法核验时不得标成 `VERIFIED`。

### 真实案例优先

默认 `case_policy=prefer_real`。与本轮目标相关的真实用户项目必须被选用，或逐项列明排除理由。不得为了满足A/B对比、补齐故事或追求戏剧性而把真实案例替换成模拟案例。

模拟场景只允许在用户明确授权，或采用 `allow_simulation_if_no_fit` 且所有相关真实案例均被有理由排除后使用；必须在计划和实际口播中明确披露。不得虚构客户、订单、金额、收入、效果、工具结果或测试数据。

## 2. 第二层｜决策：先比较，再选入口

每个决策包必须包含至少三个营销入口候选。候选必须在目标用户任务、真实痛点、钩子机制、点击理由、承诺收益、证据路径或商业价值上存在实质差异；只换词、换句式或换标题不算不同方案。

每个候选记录：
- 目标用户及其当前任务/痛点；
- 用户为什么会点、为什么愿意继续看；
- 标题/开场承诺和正文能够兑现的具体收益；
- 可用证据、制作资源和交付路径；
- 商业价值、风险、反证及不适用边界；
- 是否选中；未选中必须写清否决理由。

只能选一个主入口，并记录比较摘要、选择理由、取舍和反证。选中入口ID必须贯穿选题计划、脚本及评审。不得默认用户原选题一定正确；若证据、兑现或商业价值不足，应明确否定并给出可执行替代。

### 内容模式路由：不能所有稿件套一种叙事

每条计划必须选择以下一种模式，并按该模式组织正文：

| 内容模式 | 正文组织方式 |
|---|---|
| `real_commercial_case` | 客户需求 → 专业判断 → 工具/方法 → 产品交付 → 真实结果 → 可迁移价值 |
| `ai_workflow_tutorial` | 原始素材 → AI处理 → 人工判断 → 实际输出 → 应用价值 |
| `design_decision_analysis` | 产品Brief → 设计约束 → 方案取舍 → 产品适配 → 判断规则 |
| `business_opportunity_analysis` | 用户机会 → 市场依据 → 商业逻辑 → 风险边界 → 行动建议 |
| `hypothetical_scenario` | 明确模拟输入 → 假设条件 → 判断过程 → 示意结果 → 适用边界；必须披露模拟 |

必须在 `story_plan` 中完成模式对应的内容设计，生成稿再用 `narrative_map` 将每个阶段绑定到实际口播台词。不能为了满足字段虚构A/B对比。`worked_example`是专业演示单元，不是统一叙事模板。

### 双标杆治理（沿用3.6.0）

- 插画商业案例与AI视频A01属于不同类型的机制参考，只提炼可迁移机制，不复制原句、金额、客户、产品或悬念表达。
- 插画案例来源状态保持 `USER_PROVIDED`，未独立核验不得升级；AI视频A01保持 `calibrated_reference_not_performance_verified`。
- 两者均不得作为自动few-shot，不得作为衍生稿评分对象，不得跨领域混用。

## 3. 第三层｜生成：15项标准必须落实到实际成品

### 15项营销表达与专业交付验收标准

| 序号 | 环节 | 必须达到的结果 | 一票否决情形 |
|---:|---|---|---|
| 1 | 用户需求 | 真实受众、共同任务、用户利益和需求来源明确 | 只站在作者角度写 |
| 2 | 选题 | 至少比较3种不同营销入口，选择有吸引力且有证据的入口 | 只有行业主题，没有用户点击理由 |
| 3 | 封面 | 主标题负责吸引，副标题补充价值、产品或信息缺口 | 主副标题重复或只有作者总结 |
| 4 | 0–3秒 | 身份唤醒、利益、反差或悬念，给出停留理由 | 自我介绍、平铺直叙 |
| 5 | 3–8秒 | 增加具体信息，预告能获得的价值 | 重复开场、空泛承诺 |
| 6 | 正文 | 按内容模式展示案例、工作流、设计判断或商业分析 | 只有常识、步骤清单、工具介绍 |
| 7 | 爽点兑现 | 实际展示专业判断、处理过程、输出结果和证据 | 标题承诺与正文脱节 |
| 8 | 能力放大 | 解释AI改变的工作、降低的门槛及人机分工，并有实际演示 | 只说AI很强、赋能、提效 |
| 9 | 痒点升维 | 从当前问题自然连接到更高层能力、机会或商业价值 | 结尾重复正文或强行互动 |
| 10 | Calling | 一个主动作、一个行动理由、一个具体用户回报 | 只有点赞、关注、评论要求 |
| 11 | 证据 | 真实案例、用户提供、公开资料、推断、模拟和未知严格区分 | 虚构客户、订单、金额、工具效果 |
| 12 | 平台 | 按抖音、视频号、小红书的用户任务和内容组织分别适配 | 一稿三发，只换语气 |
| 13 | 口播 | 真人朗读自然、实际时长匹配、镜头和素材能够执行 | 文字漂亮但无法自然拍摄 |
| 14 | 独立验收 | 逐稿盲审、证据引用、独立评审、真人试读和用户盲读 | 生成模型自评后自行放行 |
| 15 | 效果回流 | 记录真实用户反馈和发布数据，定位失败原因并形成下一轮动作 | 把内部评分或模型判断当成爆款证明 |

### 关键生成要求

- 封面主副标题必须共同建立用户点击理由，不是作者总结。
- 0–3秒建立停留理由；3–8秒必须新增信息，不能重复。
- 正文必须兑现标题与开场承诺；展示实际专业判断、取舍、操作和结果，不以步骤数量代替价值。
- 能力放大只在适用时提出。任何“一个人完成、替代团队、节省人力、降低成本、提高产能”等主张必须绑定可用演示/证据，并说明AI与人的边界；没有证据就删除或降级主张。
- Calling要承接正文已兑现的价值，给出用户下一步能获得的具体收益；不能把评论、点赞或私信本身当成用户收益。
- 平台适配必须体现在选题入口、用户任务、信息密度、表达和转化动作，不是同一篇稿件简单改语气。
- 真实商业案例、AI工作流、设计决策、商业机会分析和模拟场景必须分别采用各自叙事模式。

## 4. 第四层｜验证：证据成立才允许通过

### A. 15项逐稿验收

每篇脚本必须在 `delivery_acceptance` 中逐项提供15个唯一标准ID。每项记录 `PASS / FAIL / PENDING / NOT_APPLICABLE`、原文引用、证据引用和具体理由。`NOT_APPLICABLE`只允许用于能力放大等确实不适用项目，并说明原因。

PASS必须绑定实际台词、实际文件或实际验证记录；不能只填写布尔值。任何一项FAIL即该稿BLOCKED；不得用其他项目的高分补偿。任何外部验证未完成，整体最多为 `VALIDATION_PENDING`。

### B. 独立评审凭证

每批评审必须绑定：
- 评审者ID与生成者ID；
- 评审者与生成者的独立会话ID；
- 人类评审或独立模型的身份/模型信息；
- 精确批次SHA、封存决策SHA和source-manifest SHA；
- 盲审包文件及SHA；
- 逐稿评审证据文件及SHA；
- 评审时间、评审方法及独立性声明。

同一身份、同一模型换角色、同一会话自评均不能算独立评审。盲审包不得包含评分、评审提示或作者导向线索。评审引用必须逐字出现在真实脚本中。凭证文件必须真实存在、哈希匹配并绑定当前批次；缺失即阻断。

### C. 真人试读、目标用户盲读和授权

- 真人试读：逐篇记录非作者朗读者、实测时长、目标时长、录音或签名记录。时长偏差超过20%必须返修。
- 目标用户盲读：逐篇3–5名目标用户；作者不得在场；记录匿名参与者、理解问题和结果。主题理解率至少80%，价值理解率至少60%；未达标不得PASS。
- 授权：每项使用的原始素材、客户案例、作品、音乐、画面、第三方内容均要记录权利状态、使用范围及凭证。无授权不得发布。

### D. 发布后效果回流

每篇真实发布稿必须记录平台、帖子ID/URL、发布时间、数据采集时间、数据来源、实际可获得指标、原始数据文件及SHA。不得补造缺失指标或将未知填成0。

效果分析必须包含：对照基准、观察到的变化、失败/成功原因、归因限制和下一步动作。样本量不足、同期变量或平台波动必须明确说明。知识库更新必须有来源、版本和人工批准，不得把一次相关性当成因果结论。

### E. 发布状态

- `BLOCKED`：任何硬门禁失败、证据链断裂或评审凭证不成立。
- `VALIDATION_PENDING`：文本与结构检查通过，但真人试读、用户盲读、授权或真实发布数据尚未完成。
- `PASS`：15项逐稿标准全部通过，独立评审凭证有效，所有要求的外部验证均有真实证据。

内部评分、自动化测试和CI只证明相应的代码/文件检查通过，不证明点击率、完播率、询盘或成交。

## 5. 保留既有领域标准与回归

- AI视频继续使用V4.1正式验证器、review routing、精确batch SHA和原评分量规。
- 插画继续使用V2.0独立评分、锁定字段、事实/授权门禁及六表工作簿验证。
- 两个赛道不得共享客户事实、标杆原句、评分权重或专用模板。
- 保留v3.5.0专业内容兑现门禁、六篇负向回归；保留v3.5.1正式V4.1接线；保留v3.6.0双标杆、真实来源优先和内容模式路由。
- 每次正式运行执行旧回归和v3.6.1新增回归。旧六篇失败稿只作负向测试，不得改造成正向few-shot。

## 6. 交付约定

正式导出前必须提供：实际脚本、15项逐稿验收表、原始证据链、独立评审凭证、真人试读/用户盲读/授权状态、平台适配说明及发布后数据状态。未发布的稿件可以作为审稿版导出，但必须明确 `VALIDATION_PENDING`，不得标记为已验证或可发布。

只报告真实运行过的测试及其日志。不能把规则存在、代码可编译、字段齐全或未运行的外部测试描述为“验收通过”。
