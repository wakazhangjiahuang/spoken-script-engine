# A/B 知识检索接线

在读取本轮原件、确定平台和赛道后，按已配置的私有 GitHub 知识库接入。优先调用 `knowledge_status`、`search_knowledge`、`read_knowledge`。使用 GitHub MCP 时，从授权配置取得仓库，核对 owner、仓库 ID 和 Private 可见性。读取根 `KNOWLEDGE-REGISTRY.json`，用完整 commit 读取 `asset_ref` 的 manifest 和分片，核对 SHA-256。manifest 中的类型、赛道、平台与状态用于定位分片。

- A 选题先检索客户决策和领域指导，再按平台加载与本题有关的公开规则或创作假设。用原件判断本轮客户和素材。插画选题工作台只用于推导和比较入口。
- B 成稿延续 A 的知识登记提交与资产提交，按确认篇目检索同任务指南和样例。在运行的内部来源清单记录知识版本、条目 ID、定位和实际用法。外部规则来源、用户案例原件、编辑样例和本轮文案承担各自的证据角色。
- A01 用作 AI 视频校准参考。六条标准样稿仍是候选。18 篇插画稿作编辑参考。仅在显式复查时读取历史样例。媒体报道和运营方自报的高表现样例按证据等级使用。需要把表现写成可核事实时，回到平台数据、可定位作品与观测口径。
- 平台披露、工作室创作假设和发布后的观察各有来源。后台数据缺失时记录待验证。其他赛道先查共用方法及本轮一手材料。
- 无配置、无权限、无匹配、校验失败分别记录原因。使用本轮可读原件继续。已有正式封存任务继续使用原固定来源。

GitHub 和 stdio 的配置示例见 [知识库接入](../../../knowledge-mcp/README.md)。
